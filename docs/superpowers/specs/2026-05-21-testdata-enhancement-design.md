# Testdata 增强设计方案

## 概述

v0.2.1 新增了大量 DDL 特性（IDENTITY、COLLATE、FK CASCADE、VIEW、SEQUENCE、EXTENSION、ALTER COLUMN TYPE USING），但配套的 testdata 和集成测试尚未覆盖。本方案旨在补齐这些缺口，同时为已有的未引用 testdata 文件编写自动化测试。

## 设计方案

采用**模块化扩展**方式，为每个新特性创建独立的 testdata 场景（与现有 `rename_example/` 风格一致），同时扩展 v1→v2→v3 演进链为 v4。

### 新增 testdata 结构

```
testdata/diff/
├── v4/                            ← v3 → v4 演进
│   ├── schema.sql                 ← v3 + IDENTITY + COLLATE + FK CASCADE
│   └── README.md
├── identity_example/              ← IDENTITY 专用场景
│   ├── v1/schema.sql              ← SERIAL id
│   └── v2/schema.sql              ← GENERATED ALWAYS AS IDENTITY
├── collate_example/               ← COLLATE 专用场景
│   ├── v1/schema.sql              ← 无 COLLATE
│   └── v2/schema.sql              ← name COLLATE "en_US"
└── objects_example/               ← VIEW/SEQUENCE/EXTENSION
    ├── v1/schema.sql              ← 基础表
    └── v2/schema.sql              ← +VIEW + SEQUENCE + EXTENSION
```

### 1. v4 演进场景

#### v4/schema.sql（源 = v3 + IDENTITY + COLLATE + FK CASCADE）

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
    username VARCHAR(50) NOT NULL COLLATE "en_US",
    email VARCHAR(100) DEFAULT 'unknown',
    created_at TIMESTAMP DEFAULT now(),
    phone VARCHAR(20)
);

CREATE TABLE posts (
    id INTEGER PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    user_id INTEGER NOT NULL,
    title VARCHAR(200) NOT NULL,
    content TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    sort_order INTEGER DEFAULT 0
);

CREATE INDEX idx_posts_user_id ON posts(user_id);
CREATE UNIQUE INDEX idx_users_username_unique ON users(username);

CREATE TYPE user_role AS ENUM ('admin', 'user', 'moderator');
```

#### v3 → v4 预期 diff

```sql
-- SetIdentity: users.id SERIAL → GENERATED ALWAYS AS IDENTITY
-- SetIdentity: posts.id SERIAL → GENERATED BY DEFAULT AS IDENTITY
-- AlterColumnCollation: users.username 增加 COLLATE "en_US"
-- DropConstraint + AddConstraint: posts.user_id FK 增加 ON DELETE CASCADE
```

### 2. IDENTITY 专用场景

```sql
-- identity_example/v1/schema.sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) DEFAULT 'unknown'
);

-- identity_example/v2/schema.sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) DEFAULT 'unknown'
);
```

预期：`SetIdentityOp`，而非 DROP COLUMN + ADD COLUMN。

### 3. COLLATE 专用场景

```sql
-- collate_example/v1/schema.sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description TEXT
);

-- collate_example/v2/schema.sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL COLLATE "en_US",
    description TEXT
);
```

预期：`AlterColumnCollationOp`。

### 4. VIEW/SEQUENCE/EXTENSION 场景

```sql
-- objects_example/v1/schema.sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) DEFAULT 'unknown'
);

-- objects_example/v2/schema.sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) DEFAULT 'unknown'
);

CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

CREATE SEQUENCE custom_order_seq
    INCREMENT BY 1
    START WITH 1000
    MINVALUE 1
    MAXVALUE 999999
    CACHE 1;

CREATE VIEW active_users AS
    SELECT id, username, email
    FROM users
    WHERE email IS NOT NULL;
```

预期：`CreateExtensionOp` x2、`CreateSequenceOp`、`CreateViewOp`。

### 5. 已有 testdata 测试补全

#### 集成测试（`cmd/migra/integration_test.go`）

| 测试函数 | 输入 | 断言 |
|---|---|---|
| `TestV3DirectoryDiff` | `diff/v1/` → `diff/v2/` | ADD TABLE comments, ADD COLUMN age, ADD ENUM VALUE guest |
| `TestV3UnsafeDropDiff_Safe` | `diff/v2/schema.sql` → `diff/v3/schema.sql` | 无 DROP 输出，有警告 |
| `TestV3UnsafeDropDiff_Unsafe` | 同上 + `--unsafe-drop` | DROP COLUMN age, DROP TABLE comments |
| `TestNestedDirectoryDiff` | `diff/nested/` → `diff/nested_target/` | ADD COLUMN email, ADD CONSTRAINT fk |
| `TestMultiSchemaDirectoryDiff` | `diff/multi_schema/v1/` → `diff/multi_schema/v2/` | ADD TABLE profiles, ADD COLUMN email/description |
| `TestIdentityColumnDiff` | `diff/identity_example/v1/` → `v2/` | SetIdentity, 非 DROP+ADD |
| `TestCollateClauseDiff` | `diff/collate_example/v1/` → `v2/` | COLLATE "en_US" |
| `TestObjectsDiff` | `diff/objects_example/v1/` → `v2/` | CREATE VIEW, CREATE SEQUENCE, CREATE EXTENSION |
| `TestV3ToV4Diff` | `diff/v3/schema.sql` → `diff/v4/schema.sql` | SetIdentity + AlterColumnCollation + FK CASCADE |

#### 解析测试（`internal/parser/handler_test.go`）

| 测试函数 | 文件 | 验证 |
|---|---|---|
| `TestParseAlterOperations` | `alter_operations.sql` | 12 种 ALTER TABLE 变体全部无报错 |
| `TestParseComplexDDL` | `complex_ddl.sql` | 复合约束、高级类型无报错 |
| `TestParseDropScenarios` | `drop_scenarios.sql` | DROP 语义无报错 |
| `TestParseEdgeCases` | `edge_cases.sql` | 边界 SQL 不崩溃 |

## 测试验证策略

每个新增测试遵循三层验证：

1. **解析正确**：SQL 文件可被 parser 无报错解析
2. **Diff 正确**：差异检测结果符合预期（操作类型、数量、内容）
3. **Render 正确**：输出的 SQL 可执行、语法正确
